## Arquitectura final

```
SQLite → Metrics → Alerts → Action Engine → buildIaPayload()
                                              ↓
                                    hashIaPayload (SHA-256)
                                              ↓
                         license_get_bi_auth (Tauri, token GC1 firmado)
                                              ↓
                         POST /interpret (Worker, auth + schema + rate limit)
                                              ↓
                         OpenAI | Workers AI → parse + validate números/acciones
                                              ↓
                         Cliente re-valida → cache v2 si payload_hash coincide
```

**Action Engine** sigue siendo la única fuente de verdad para orden/urgencia.  
**IA** solo devuelve `summary`, `insights`, `action_explanations[]`, `caveats[]`.

## Mecanismos implementados

### Autenticación (C1, C4)
- Token **GC1** Ed25519 (misma clave pública que license-api).
- Cliente: `invoke("license_get_bi_auth")` → Bearer + `machine_id` + `show_profits`.
- Worker verifica firma, `machine_id`, y `hasBusinessIntelligence()` (billing `monthly` o `trial`).
- Plan **perpetual/free** no puede consumir el Worker con curl/Postman sin token válido.

### Rate limiting
- In-memory por `{lid}:{machine_id}` según plan (~20/día basic).
- HTTP 429 con `retry_after_sec`.

### Schema payload (H4/H5)
- Rechaza `{}`, `null`, arrays raíz, campos extra, payloads >48KB.
- HTTP 400 antes de invocar modelo.

### Validación numérica (C2)
- `buildAllowedNumberSet()` recorre payload + variantes (%, miles, redondeos).
- Rechaza cifras no justificables en summary/insights/explicaciones/caveats.
- Retry 1x con instrucción de corrección; si falla → 422 mensaje controlado.

### Validación prioridades (C3)
- `priorities[]` rechazado en parse/sanitize.
- Solo `action_explanations[]` con `action_index` 0..N-1.

### Estimaciones (Fase 5)
- Regex anti “utilidad exacta / margen exacto / ganancia real”.
- Prompt exige “utilidad estimada”, “margen estimado”, “cobertura estimada”.

### Entitlements (C4, H1)
- Sidebar, página, payload, llamada Worker protegidos por `businessIntelligence`.
- `show_profits` server-side: sin permiso → `profit_estimated` eliminado del payload.

### Cache (H2)
- Key `walqo-bi-interpretation-v2`: `{ payload_hash, computed_at, interpretation }`.
- Invalida si hash o `computed_at` cambian.

### Refresh snapshot (H3)
- Evento `walqo:intelligence-data-changed` (venta/anulación).
- Polling 45s + visibility + LAN pending drop (20s).

### LAN freshness (Fase 9)
- Banner antes de acciones e IA en `/asistente`.

### Offline UX (Fase 10)
- Aviso antes de generar; botón “Reintentar interpretación”; métricas/acciones no bloqueadas.

## Riesgos restantes

1. **Rate limit in-memory** — se resetea por isolate Worker; suficiente para abuso casual, no para ataque distribuido masivo. Mitigación futura: KV/Durable Objects.
2. **Validación numérica** — tolera redondeos comunes pero no cubre todo lenguaje natural ambiguo; falsos positivos posibles en textos muy creativos.
3. **Nombres de entidades** — validación de nombres de producto/cliente es conservadora; no bloquea todos los casos edge.
4. **Trial BI token** — depende de license-api online para emitir token; offline >14 días sin token mensual almacenado → sin IA (métricas locales OK).
