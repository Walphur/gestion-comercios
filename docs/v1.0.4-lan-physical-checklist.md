# v1.0.4 — Checklist Sync LAN (2 PCs físicas)

**Estado:** UNTESTED (no se ejecutó en esta pasada)  
**Regla:** no marcar PASS sin corrida física. No modificar Sync LAN para “arreglar” el checklist.

## Preparación

1. Dos PCs en la misma red LAN (Wi‑Fi o cable).
2. Misma versión de WalQo en ambas (instalador o build de release).
3. Licencia activa con BI si se va a mirar Inteligencia (plan mensual / trial).
4. PC A = host; PC B = cliente.

## Pasos

| # | Acción | Resultado esperado | OK? |
|---|--------|-------------------|-----|
| 1 | En A: activar Sync LAN / modo host; anotar IP/puerto | Host escuchando | ☐ |
| 2 | En B: conectar al host A | Estado “connected” / sincronizado | ☐ |
| 3 | En A: crear/editar producto o venta | Evento llega a B | ☐ |
| 4 | Desconectar red de B unos segundos | Banner/estado disconnect; `pendingEvents` > 0 si hay cola | ☐ |
| 5 | Reconectar B | Sync done; pending vuelve a 0 | ☐ |
| 6 | Provocar conflicto (mismo registro editado offline en A y B) | UI de conflicto / `conflictCount` > 0 | ☐ |
| 7 | Resolver conflicto y sync | Estado limpio | ☐ |
| 8 | Con LAN activo, abrir `/asistente` (Inteligencia) | Métricas locales; si hay pending/stale, aviso de frescura | ☐ |
| 9 | Tras sync limpio, generar interpretación IA (online) | Hash/cache coherente; sin datos inventados | ☐ |

## Evidencia a guardar

- Capturas de host connected / disconnect / conflict / sync done
- Hora, versión de app, IPs
- Notas de fallos (no inventar PASS)

## Criterio de cierre

- Los 9 pasos OK → LAN **PASS** en readiness  
- Cualquier paso fallido → LAN **FAIL**  
- Sin corrida física → LAN **UNTESTED** → release **NOT READY**
